## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`.gitignore` excludes Chrome Store zips and PNG screenshots, but `chromestore/store-listing.md` references specific ready assets and zip filenames. A clean checkout will not contain the documented submission artifacts. Either track the required store assets intentionally, generate them in a release lane, or update the docs to describe where they are produced and retrieved.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A clean checkout plus documented commands can reproduce every Chrome Store asset referenced by store-listing.md.
- [x] #2 Store-listing metadata no longer marks ignored/missing files as ready unless they are generated by the documented process.
- [x] #3 The repository policy is explicit about which Chrome Store assets are tracked versus generated.
- [x] #4 Release or submission docs include a validation step that checks referenced asset files exist.
<!-- AC:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
store-listing.md marked `icon-128.png` and the screenshot "✓ ready" while both were git-ignored (`chromestore/*.png`), so a clean checkout lacked them. Fixed: the real store screenshot is now tracked under `chromestore/assets/` (the `chromestore/*.png` glob doesn't match the subdir, so it commits without a .gitignore change); the redundant loose `chromestore/icon-128.png` was removed and the store icon now references the tracked `extension/icons/icon-128.png` (the extension icon is the store icon). AC#1: a clean checkout now contains the icon + screenshot, and `./scripts/package-extension.sh` reproduces the zip. AC#2: the Assets table no longer marks ignored/missing files "ready" — each row states tracked vs generated with the real path. AC#3: an explicit "Asset policy" section distinguishes tracked (icon + chromestore/assets/) from generated (zip) and flags loose `chromestore/*.png` as non-authoritative scratch. AC#4: a copy-paste validation snippet fails if any referenced asset is missing.
<!-- SECTION:FINAL_SUMMARY:END -->
